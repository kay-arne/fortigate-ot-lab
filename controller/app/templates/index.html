Vul de stappen hieronder in. Zodra alle verplichte onderdelen groen zijn, kun je onder 2. Lab het lab uitrollen. Elke kaart heeft een eigen Opslaan-knop.

    1 Proxmox-verbinding

    De controller beheert de Proxmox host via SSH: hij voert daar qm, pct en pvesh uit en kopieert bestanden via SFTP. De OT-containers worden met pct exec bediend, dus niet via het netwerk. Deze gegevens zijn door de installer vastgelegd (/opt/otlab/data/host.json); wijzigen doe je door de installer opnieuw te draaien.

    2 FortiGate-VM image

    Download in de Fortinet support portal (Support → VM Images → FortiGate → KVM) het bestand FGT_VM64_KVM-v7.6.x-...out.kvm.zip, pak het uit en upload de fortios.qcow2. Het image wordt naar de host gekopieerd bij het uitrollen.

    Huidig: geen

    3 FortiGate WAN (port1)

    port1 is de enige verbinding tussen je fysieke netwerk en het OT-lab. Hij hangt aan -. Op dit adres bereik je de FortiGate-GUI en via dit adres praat de controller met de FortiGate REST API. Wijzigingen gelden bij de eerstvolgende uitrol van de FortiGate.

    Met een statisch IP kan de controller de FortiGate na de eerste boot direct vinden.
    Een vrij adres in het netwerk van de uplink-bridge.
    Router naar internet; verplicht. Zonder default route geen FortiGuard en geen licentie-activatie.
    Bij DHCP weet de controller het adres niet vooraf. Zoek het na de eerste boot op (DHCP-server of FortiGate-console) en vul het hier in.
    Nodig om FortiGuard en FortiFlex (licentie) te bereiken. Leeg = FortiOS-standaard: FortiGuard-DNS via DNS-over-TLS (tcp/853), wat veel netwerken blokkeren.
    De FortiGate is ook DNS-proxy voor de OT-segmenten en gebruikt deze servers als upstream.

    Deze instellingen gaan via cloud-init mee bij de eerste boot. Na een wijziging de FortiGate opnieuw uitrollen (VM verwijderen via Afbreken… en daarna Deploy lab).

    4 FortiGate-beheer

    Het wachtwoord van gebruiker admin wordt bij de eerste boot via cloud-init gezet. De controller gebruikt het om via SSH een REST API-gebruiker aan te maken; daarna werkt hij met de API-key.

    Minimaal 8 tekens, geen aanhalingstekens. Na de uitrol wijzigen heeft geen effect op een draaiende FortiGate.
    API-gebruiker otlab-controller, alleen toegestaan vanaf het IP van de controller. Wordt na de eerste boot aangemaakt.

    5 Licentie

    De licentie gaat via de cloud-init config drive mee bij de eerste boot. Voor de OT-signatures (industrial database) in application control en IPS is de OT Security Service nodig.

    Huidig: geen
    De FortiGate heeft internettoegang via port1 nodig om het token te activeren.
    De OT-simulators in de containers zijn ouder dan de code van de controller (na een update).

    Ad-hoc test

    Bijv. scan 10.20.0.0/24 22,80,502, tcp 10.30.0.10 8080, modbus-read 10.10.0.30 0 4, s7-read 10.10.0.20, http http://10.30.0.20/

    Controller bijwerken

    De controller is een git-checkout van kay-arne/fortigate-ot-lab in /opt/otlab. Bijwerken haalt de nieuwste versie op, werkt de Python-dependencies bij en herstart de controller. Je instellingen, uploads, API-key en testresultaten staan in data/ en blijven behouden. Het draaiende lab (FortiGate en containers) wordt niet aangeraakt.
